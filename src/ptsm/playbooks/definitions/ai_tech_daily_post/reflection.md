# AI 科技资讯 Reflection

先按 `# AI Tech Evidence Contract` 的 mode 逐项核对。任何一项缺失都要求重写，不要用更顺的文案掩盖证据空洞。

## 通用

1. 是否只使用合同中的安全主题、标签、事实、测试记录和受众决定？
2. 是否没有 URL、原始标题、作者、来源、feed、来源标识或热点原文？
3. 标题是否具体、短，正文是否以短行扫读，而不是发布会通稿、长解释或硬塞互动？
4. 是否保留 `#AI资讯`，并避开收益、投资、万能、全自动、绝对性能等承诺？

## `news_brief`

1. 是否恰有 3–5 条独立事件？
2. 每条是否都出现合同中的事件标签和至少一条对应事实？
3. 是否没有“我实测、我用了、亲测、明显更快”等体验或性能语言？
4. 是否没有把趋势热度、主观感受或额外影响判断塞进事实卡？

## `hands_on`

1. 是否只有一个主题，且逐字包含产品、版本、测试日期、任务、输入摘要、观察输出和局限？
2. “实测/复盘/结果”是否只描述这次记录，而不是泛化为产品能力或性能承诺？
3. 是否明确保留了局限和人工核对点？
4. 若主题是提示词，是否只写测试输入摘要，而非可直接复制的通用模板或完整私密对话？

## `fact_translation`

1. 是否只有一个主题，并逐字包含至少两条合同事实？
2. 是否逐字包含“谁该关注”和“谁可以等等”的决定？
3. 是否没有第一人称体验、实测、性能感受、未来预测或站队推荐？

任一 mode 的必要字段、事实或局限缺失，或出现不在合同内的事实性正文句，就必须重写。
