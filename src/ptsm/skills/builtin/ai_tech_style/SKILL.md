# AI Tech Style

先读运行时提供的 `# AI Tech Evidence Contract`。它是唯一可写入正文的事实边界；热点、自由场景和选题方向只能帮助选题，不能当证据。

## 选一个模式，不混写

| 模式 | 小红书正文形状 | 必须出现 | 禁止出现 |
| --- | --- | --- | --- |
| `news_brief` | 3–5 条编号事实卡 | 每条的标签和已核验事实 | 第一人称、实测、性能感受、单项长评 |
| `hands_on` | 一次短实测记录 | 主题、产品、版本、日期、任务、输入、观察输出、局限 | 通用 prompt、虚构结果、效率承诺 |
| `fact_translation` | 一条事实转译卡 | 主题、至少两条事实、谁该关注、谁可以等等 | 第一人称体验、预测、泛泛感想 |

不要在同一条里混合快讯、体验和解释。没有对应合同字段就不要写。

## 短而有活人感

- 标题 12–22 字，封面一句不超过 18 字。用具体变化、任务或判断边界开门；少用“重磅、颠覆、今日更新、万能模板”。
- 正文优先 3–7 个短行。能用一个顿号、破折号或“先看这条”停顿的，不写成完整讲义。
- 网感靠节奏和取舍：`这次更新，不是所有人都要追`、`先看事实，再决定要不要动`。这类标题不能在正文外推为新事实。
- 不写 PR 通稿、参数罗列、投资建议、收益承诺、全自动承诺，也不拿热点热度替代事实。
- 保留 `#AI资讯`；不要为凑互动另造“收藏、评论区、你会用吗”之类没有证据的正文句。
- 旧的“3秒核心信息”“普通人影响”“收藏清单”在这里分别收敛为首条事实、受众边界和事实卡，不是额外的通用段落；不靠一句“非投资建议”掩盖投资暗示。
- 不把工具拟人化成万能的“AI 生活搭子”；只写合同中已经记录的任务、事实或测试范围。

## 三种可执行模板

### `news_brief`

```text
1. {标签}｜{已核验事实}
2. {标签}｜{已核验事实}
3. {标签}｜{已核验事实}
```

按合同扩到四或五条。每一行都必须含对应标签和事实，不加“我看下来”“明显更强”“值得冲”等补充。

### `hands_on`

```text
{主题} 实测记录
{产品}｜{版本}｜{测试日期}
任务：{任务}
输入：{输入摘要}
观察：{观察输出}
局限：{局限}
```

可以短，不可以漏。提示词只能作为`输入`的摘要，不能输出一整段供读者照抄的万能模板。

### `fact_translation`

```text
{主题}
事实：{已核验事实 1}
事实：{已核验事实 2}
该看：{谁该关注}
可等：{谁可以等等}
```

每一行都保留合同原文，避免“所以肯定更好”“我用了很稳”“普通人都要学”一类扩写。

## 绝对边界

- 不写 URL、域名、原始标题、来源作者、feed、来源 ID 或采集过程。
- `news_brief` / `fact_translation` 不写 `我`、`实测`、`亲测`、`刚刚试了`、`体验`。
- `hands_on` 的第一人称只能指向该条已记录测试，且不能越过观察输出和局限。
- 不做可复制 prompt 教程。想写 prompt，必须进入 `hands_on`，完整交代一次真实测试的任务、输入、输出与局限。
