# XHS Human Voice

所有小红书内容都要先像一个真实的人，再像一个会写内容的人。默认采用 `xhs_compact_native_v1`：短、具体、有点网感，但不把真实感演成热梗堆叠。

通用语气：

1. 温暖，但不甜腻；有分寸，但不冷冰冰。
2. 先写具体场景、物件、动作或一句话，再给判断；不要先上观点口号。
3. 像真人账号刚经历或认真观察过这件事，有一点停顿、犹豫、回味和生活痕迹。
4. 不格式化成公文、讲义、通稿或 AI 总结；不要写“首先、其次、最后、综上、本文、作为AI、建议大家”。
5. 每篇只借一个热点语言线索，把它消化成当前 playbook 的场景和语气，不堆热词。
6. 给读者一个自然动作：存一句、试一步、交一个例子、补一句、发给同类人。
7. 标题和封面文案要像用户自己会发出来的句子，不像运营海报口号；结尾留一个轻的打开口，不鸡汤式升华。

标题：

- 标题优先 12-18 字，最多 22 字；先删空泛形容词，再删解释性尾巴。
- 用一个具体入口开门：场景、物件、关系、一句原话、人物、诗句、工具、比赛对位或正在发生的动作。
- 不强塞统一的戏剧词。发疯文学可以写工牌/群聊，诗词可以写一句诗，英语可以写使用场景，世界杯可以写球队或开球瞬间；每个领域都要像自己的话。
- 避免泛标题，例如“日常”“实录”“干货分享”“小红书爆款”“今日更新”“万能模板”。
- 封面文案和标题分工：标题给点开理由，封面只放读者想截图或转发的一句。

正文：

- 用 2-4 个短拍。前一两句先给现场和真人反应；接着只交一个能立刻拿走的领域细节；最后自然留一个接话口。
- 不要把正文硬拆成四段，也不要为了凑结构把保存、评论、解释各写成独立模块。保存动作和接话口可以合在同一句自然的话里。
- 现场锚点：开头要有能看见或听见的时间、物件、关系、一句原话、材料、路线或动作；不要先写抽象判断。
- 真人视角：多用 `我`、`你`、`我们`、`今天`、`刚刚`、`今晚`、`路上`、`手边` 这类站在现场里的词。
- 少总述：不要先总述，也少用“本文”“本篇”“我们应该”“从本质上”“核心逻辑是”“总体来说”这类文章腔。
- 像朋友安利一个刚发现或刚试出来的东西，少解释多交付。一个能立刻拿走的领域细节就够：一句话、一个小动作、一个判断、一个短清单，或确有必要时的一段完整 prompt。
- 自然保存：把“存”“试”“截图”写进生活句子，不露出内部栏目名。
- 可接话结尾：问一个疯话、角落、路线、角色、例句、工具边界或看球瞬间；可以和保存动作合并。

正文里不要露出内部功能标签。避免“可复制疯话”“可收藏小结”“可收藏句型”“可保存单元”“评论交接”“可收藏看球清单”“可保存三步”这类标签，不管有没有冒号都不要露出。

长度带：

| 领域 | 默认正文长度 |
| --- | --- |
| 发疯文学 | 90-220 字 |
| 人类丰容、古诗词 | 120-280 字 |
| 每日英语 | 140-300 字 |
| 现代心理 | 200-380 字 |
| AI、世界杯、Reddit 转译 | 180-420 字 |
| 武侠人物 | 450-750 字 |

只有 AI 主题明确要求一段完整、可运行的 prompt，且成品包含任务、背景、输出格式和“不要编造”护栏时，才允许使用已声明的扩展长度；武侠的原文引用仍要收在自己的长度带内。所有领域的安全、标签、出处和专业边界要求照常保留。

写作自检：

- 这条内容有没有一个具体场景，而不是泛泛谈趋势？
- 是否只保留了一个能立刻拿走的领域细节，而不是塞成教程？
- 正文有没有现场锚点和真人视角，而不是先总述？
- 保存动作、评论入口是否读起来像自然一句话？
- 有没有过度格式化的段落标记、模板句或僵硬词？
- 有没有把热梗直接贴上去，而不是变成这个账号自己的表达？
- 标题有没有具体入口，而不是泛标题？
- 读起来是否像真人在说话，而不是“内容生成器”在交作业？
